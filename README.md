# 多平台店铺销售日报

基于京东商智（POP/自营）、唯品会、拼多多导出的商品数据，通过 **DuckDB + Vercel Serverless Function（Flask）** 生成交互式销售日报。支持多平台、多店铺整合展示与平台切换。

**线上地址**：https://sales-report-self.vercel.app

---

## 架构

```
┌──────────────┐     fetch      ┌──────────────────┐     read     ┌────────────────┐
│ index.html   │ ──────────────→│ api/data.py      │─────────────→│ report.duckdb  │
│   ~127KB      │←──── JSON ─────│ (Flask Function) │←──read_only──│   ~7.3MB       │
└──────────────┘                └──────────────────┘              └────────────────┘
      数据源: ~/Desktop/Platform-Date/*（符号链接 → iCloud 云盘，见「数据源目录」）
             └── scripts/build_all_shop_daily.py 构建入库 ──┘
```

| 组件 | 大小 | 说明 |
|------|------|------|
| `index.html` | ~127KB | 轻量 HTML，运行时 fetch `/api/data` 加载数据 |
| `api/data.py` | ~7KB | Flask 入口（`app`），读 DuckDB（read_only）返回 JSON |
| `api/report.duckdb` | ~7.3MB | 函数打包读取的数据库副本（构建后自动同步） |
| `api/data/report.duckdb` | ~8.4MB | 构建主输出（11 张表，含 city_stock 城市库存） |

> ⚠️ Vercel 文件系统只读，duckdb 必须 `connect(path, read_only=True)`；
> ⚠️ 新版 Python runtime 只支持 Flask/ASGI `app` 入口，不再支持裸 `handler`。

## SKU 类目人工改写

部分商品在平台源表中的类目归属不准，可通过映射表强制覆盖（全平台生效，作用于 SKU 明细与类目聚合）。

**文件链路**：桌面 CSV（运营编辑）→ `scripts/csv2category_json.py` 转换 → `scripts/category_override.json`（入库）→ 构建时扫描 JSON 改写类目。

**操作步骤**：

```bash
# 1. 运营编辑桌面映射表（Excel 可直接打开 CSV，列：一级类目,二级类目,三级类目,SKU）
#    路径：~/Desktop/Platform-Date/SKU_Info/category_override.csv

# 2. 转换为 JSON（自动校验表头/空值/SKU 冲突并提示）
python3 scripts/csv2category_json.py

# 3. 提交 JSON 入库（git 可 diff，误改可回滚）
git add scripts/category_override.json && git commit -m "chore: 更新SKU类目映射"

# 4. 重建生效
python3 scripts/build_all_shop_daily.py
```

**约定**：
- 同一 SKU 在 CSV 中重复且类目不同时，后者覆盖前者，脚本会输出冲突清单
- JSON 不存在或解析失败时构建仅告警跳过，不阻断
- 已弃用 xlsx 格式（二进制无 diff、解析坑多），映射一律走 CSV

## 店铺数据起始日期（shop_start_dates.json）

`scripts/shop_start_dates.json` 配置各店铺的数据起始日期（开业/接入日）。早于该日期的空报表与缺失组合视为**店铺开业前的正常形态**，构建跳过解析且**不计入**「数据不全/空文件」告警，避免误报为下载故障；开业后的空表仍正常提醒。

```json
{
  "startDates": {
    "jd|认养一头牛冲饮奶粉旗舰店": "2026-09-17"
  }
}
```

- key 为内部店铺 key（`平台|店铺名`），value 为 `YYYY-MM-DD`
- 新店铺开业时加一行即可；未配置的店铺不受影响
- 作用于京东POP/自营、拼多多、天猫、唯品会全部平台的空报表跳过逻辑

### 京东自营双口径

京东自营有两类源文件，按 `(日期, 店铺)` 合并为唯一一行：

| 源表 | 文件 | 口径 | 字段 |
|---|---|---|---|
| 经营状况商品明细 | `{店铺}_经营状况商品明细_YYYY-MM-DD.xlsx` | 零售成交 | 成交金额/件数/单量/人数、访客、PV、加购 |
| 店铺排行 | `{店铺}_店铺排行_YYYY-MM-DD.xlsx` | 零售成交（店铺级去重） | 覆盖店铺行成交金额/件数/单量/人数、访客、PV——修正明细表分 SKU 累加导致访客重复计数、转化率低估的问题；无 SKU 明细，当日缺失时回退明细表累加口径 |
| 供应链库存-商品明细 | `{供应商}_自营商品明细_YYYY-MM-DD.xlsx` | 供货出库 | 出库金额（采购价×昨日出库件数）、出库件数、可用库存额、近30日出库额 |

- **窗口累计文件自动跳过**：经营状况表「时间」列含「至」（如 `2026-09-01至2026-09-25`）为区间累计而非单日快照，跳过并记录到 `quality.windowFiles`。
- **派生指标**：零售/出库比、库存周转率（近30日出库额÷可用库存额）、库存周转天数。
- **前端展示**：所有平台基础版式一致（GMV=成交金额）；选择京东自营时，核心 KPI、店铺表现、类目结构、当日 SKU、7日优化研究、GMV 归因各表末尾追加「出库金额」（及 KPI/归因的「出库件数」）列/卡；另有「自营双口径 KPI」「自营库存健康」两个专属 section。
- **缺失数据源显示 —**：如某店铺只有库存表无经营状况记录（如飞鹤成人），零售列显示 `—`，数据源状态列标注「仅库存」；明细表（X月店铺销售总览）中零售指标（GMV/件数/单量/客户/访客/转化/客单价/UV价值/退款率/SKU数）在零售数据全 0 时统一显示 `-` 而非 0（`hasRetail()` 判定）。

### 头部商品城市库存预警

- **数据来源**：供应链库存表纵版长表（每 SKU 一行 `RDC=全国` 全国合计 + N 行分仓明细，`RDC` 值剥离 FDC/配送中心/本地仓中心/城市/大商超/零售/补货B 等后缀后归一），取 8 个主要 RDC：北京 / 上海 / 广州 / 成都 / 武汉 / 沈阳 / 西安 / 德州（`MAIN_CITIES`）。注意城市列只覆盖部分主力仓，城市合计 ≠ 全国库存（全国值取 `RDC=全国` 行）。
- **范围**：近7日出库 TOP 20 SKU × 上述 8 城市（`HEAD_CITY_LIMIT` / `MAIN_CITIES`，位于 `build_all_shop_daily.py`）；`是否售完即止=是` 的 SKU 在圈选前整行剔除，不进入本模块。
- **落库**：DuckDB 表 `city_stock(date, shop, sku, name, city, stock, daily_avg, days_cover, out_yesterday, out_7d, nat_stock, nat_days_cover, nat_transit, nat_out_yesterday, nat_out_7d, price)`。
- **预警分级**：`days_cover = 城市库存 ÷ SKU近7日日均出库`；<1 天 → 断货风险（红），1~3 天 → 偏低（黄），≥3 天 → 正常，无出库 → unknown。
- **全国口径**：`nat_stock` = `RDC=全国` 行现货库存件数；`nat_days_cover` = 全国库存 ÷ 全国行近7日日均出库；`nat_transit` = 全国行采购在途数量；`nat_out_yesterday` / `nat_out_7d` = 全国行昨日/近7日出库件数（无全国行的 SKU 以分仓合计兜底，该导出格式下两者一致）。
- **展示范围**：模块店铺白名单 `MODULE_SHOPS_FILTER.city_alert`（`white` 非空时仅展示名单内店铺，`black` 始终排除；单选店铺不在名单内时整个模块隐藏）。数据层全店铺解析入库，展示层按白名单裁剪。
- **前端**：「头部商品城市库存预警」表格（仅京东自营视图可见）：一行一个 SKU，横向展示 8 城市库存/覆盖天数，附采购价、昨出库、近7日出库（以上三项均为全国行口径）、全国库存、采购在途与全国覆盖天数；按最差城市覆盖天数升序排列，风险格着色。
- **口径注意**：个别日期导出未勾选城市字段时该日数据缺失显示 —；头部 SKU 按全表昨日出库选取，落在无出库店铺分组的行 `days_cover` 为 null（unknown）。

| 框架字段 | 源列 |
|---|---|
| `gmv` / `orderAmount` | 成交金额 |
| `units` | 成交件数 |

**已知缺失**（源表无对应数据，按 0 处理）：

| 字段 | 原因 | 影响 |
|---|---|---|
| `searchImpressions` / `searchClicks` | 无搜索维度 | 搜索曝光/点击/CTR 恒 0 |
| `productImpressions` / `productImpressionUsers` | `曝光用户数` 列存在但全 0 | 曝光漏斗失效 |
| `refundAmount` | 仅 `近30日` 滚动累计，与日粒度 GMV 不同口径 | 退款率恒 0，退款偏高预警不触发 |

> `近30日成功退款金额` ÷ 当日 `成交金额` ≈ 1043%，不可直接作为日退款；同行均值、推广策略、各类环比等 35 列按「不新增字段」原则过滤。

## 快速开始

### 日常更新（标准流程）

```bash
cd ~/Documents/GitHub/sales-report

# 1. 构建（自动读取各平台目录，自动同步 db 到 api/）
python3 scripts/build_all_shop_daily.py

# 1b. 增量构建：只重新解析指定平台的源文件，其余平台用上次缓存
#     （聚合/指标/图表/落库仍全量重算，口径与全量一致；首次使用前需先跑一次全量）
python3 scripts/build_all_shop_daily.py -p vip        # 或 --platform jd / pdd / jd_self / tmall / vip_jitx

# 2. 提交推送（push 即自动触发 Vercel 部署）
git add -A && git add -f templates/api/report.duckdb templates/api/data/report.duckdb
git commit -m "report $(date +%m-%d)" && git push
```

> 增量模式说明：缓存位于 `scripts/.build_cache/<平台>.pkl`（平台解析中间产物，自动维护）；某平台当日在后台导出新文件后只需 `-p 该平台` 重跑，无需等全量解析其余平台目录。`config.py` 的 `SHOPS`/`SHOP_TARGETS` 变更影响所有平台时应跑全量。

### 本地预览

```bash
conda activate      #开启虚拟环境
python3 templates/server.py    # 启动本地预览服务器
# 浏览器打开 http://127.0.0.1:8081（强刷 Cmd+Shift+R）
# ⚠️ 不要直接双击 HTML，必须通过 http:// 访问
```

**启动前自检（重要）**：`server.py` 依赖 `duckdb`，必须用装有该依赖的 Python 启动。若终端 `python3` 解析到系统/Xcode Python（无 duckdb），页面会**完全无数据**（API 返回 `{"error": "duckdb not installed"}`，页面空白或无店铺）。

```bash
which python3                       # 确认 python3 指向（期望 miniconda/conda 路径）
python3 -c "import duckdb; print('ok')"   # 能打印 ok 即可正常启动
```

若解析到系统 Python，用绝对路径启动（绕过 PATH）：

```bash
/opt/miniconda3/bin/python3 templates/server.py
```

**常见故障排查**：

| 现象 | 原因 | 处理 |
|------|------|------|
| 页面无任何数据/店铺 | 启动用的 Python 未装 duckdb（典型：Xcode Python 3.9） | 按上述自检换 conda Python 重启 |
| 启动报端口占用（Address already in use） | 8081 已有 server.py 进程（可能上次未退出） | `lsof -iTCP:8081 -sTCP:LISTEN` 查 PID，`kill <PID>` 后重启，或直接复用现有进程 |
| 页面数据不是最新 | 构建后未重启/浏览器缓存 | 强刷 Cmd+Shift+R（server.py 已带 no-cache 头，一般无需；server.py 以 read_only 打开数据库，构建与预览可并行） |
| API 正常但页面报 fetch 失败 | 用 `file://` 双击打开了 HTML | 必须走 `http://127.0.0.1:8081` |

**验证 API**：`curl -s http://127.0.0.1:8081/api/data | head -c 200` —— 返回 JSON（含 `generatedAt`/`shops` 等字段）即正常；返回 `{"error": ...}` 按上表排查。

| 级别 | 类型 | 条件 |
|------|------|------|
| 🔴 高危 | GMV下滑 | 环比 ≥20% 且 ≥¥500 |
| 🟡 关注 | 流量下滑 | 环比 ≥30% 且 ≥100人 |
| 🟡 关注 | 转化走弱 | 低于前日 75% 且下降 ≥1pp |

| ⚪ SKU | SKU大幅下滑 | 减少 ≥¥500 且降幅 ≥50% |
